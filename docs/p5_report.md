# P5(병렬 Branch-and-Cut · 튜닝 · 최종 리포트) 결과 보고

작성일: 2026-11-20 · 대상: `docs/design.md` 6장의 P5 · 결론: **게이트 충족(프로젝트 P0~P5 완결).**
4스레드 병렬 Branch-and-Cut 트리(`LpSolver::clone` + `BnbTeam` 협동 워커 풀)와 SC/SPP 동적 스레드 전환·조밀 SC 컷 밀도 선별·`scpnrh` 트리 반환 튜닝을 구현했다.
153개 전체 벤치마크(30초, 4스레드, 전 seed 증명 기준)에서 **132/153개 최적 증명(SC 74/90, SPP 58/63)**을 달성해 P4(125개) 대비 **+7개 신규 증명(손실 0개)**, **HiGHS(120개) 대비 +12개 우위(HiGHS만 증명한 인스턴스 0개)**, **Gurobi 비교 가능 71개에서 67/71 동률**을 기록했다. 양쪽 모두 증명한 120개 기준 HiGHS 대비 증명 시간 합은 **98.86초 vs 367.74초(3.72배 단축, 기하평균 비 0.22, 100/120 승)**이며, SPP 62개 해 품질에서 HiGHS 대상 **10승 52무 0패(무패)**, SC 40개 해 품질에서 Gurobi 대상 **5·10·30초 전 구간 0승 40무 0패(+0.000%)**를 달성했다.

## 1. 구현한 것

| 구성 | 파일 | 내용 |
|---|---|---|
| LP 복제 및 조기 중단 | `include/scsp/lp.hpp`, `src/core/lp.cpp` | `LpSolver::clone(seed, time_limit, stop)` 구현: 루트 컷, 열 경계, 최적 기저 및 dual steepest edge 가중치를 워커별 독립 LP 인스턴스로 복제. `LpOptions::stop` 원자 플래그를 심플렉스 루프(32반복마다)에서 검사해 최적 증명·포기·시간 종료 시 워커를 즉시 정리 |
| 병렬 Branch-and-Cut 트리 | `include/scsp/bnb.hpp`, `src/core/bnb.cpp` | `BnbTeam` 협동 워커 풀과 공유 최선-하한(`open`) 우선순위 큐 구현(Gendron & Crainic 1994). 워커별 독립 `LpSolver`·`local_fix`·`global_fix`를 유지하고, 전역 하한 `min(open, active_bound)` 및 O(1) 평균 의사비용(pseudocost) 통계를 동기화. 워커 중간 이탈 시 진행 노드를 `open`에 반납해 유실·데드락 차단 |
| SC 동적 워커 합류 및 반환 튜닝 | `src/core/sc_solver.cpp` | 트리가 유효하게 gap을 좁히는 중(`strikes == 0`)이고 휴리스틱이 정체(`0.8s / 1.8s / 3.5s`)되거나 gap이 좁으면 휴리스틱 워커(1→3→0 순)가 `BnbTeam::help`로 B&B 트리에 합류. 정수 비용 대형 문제의 `skip_tree` 기준을 `max(300, 100 × (thr - z))`로 강화하고 `H.keep` 판정 지연을 수정해 `scpnrh` 트리 반환을 6~26초 → 0.12~0.18초로 단축 |
| SPP gap 기반 병렬 B&B / LNS 배분 | `src/core/bin_solver.cpp` | 첫 해 탐색 전(`ub == INF`)에는 4스레드 전원 트리 탐색 지원. 해 확보 후 넓은 gap(≥ 5%)에서는 `1 B&B + 3 LNS`로 대형 합성 `sp` 해 품질을 유지하고, gap이 `< 5% / 3.5% / 1.5%`로 좁아질수록 워커 1·2·3을 순차적으로 병렬 B&B에 투입 |
| 조밀 SC 컷 밀도 선별 | `src/core/bnb.cpp` (`root_cuts`) | 정수 덮기 문제(`cuts == 1 && integral`)에서 추가된 컷의 비영 비율(`cut_nnz / nnz0`)에 비례해 최소 gap 감소 유지 기준(`max(0.05, 0.25 × cut_nnz / nnz0)`) 적용 |
| 단위 테스트 · 참고문헌 대조 | `tests/test_p5.py`, `docs/references.md` | 병렬 B&B 일관성·warm start·조기 포기 테스트 8건 추가(총 **170/170 통과**, `-Wall -Wextra -Wpedantic -Werror` 빌드 통과). 미대조 문헌 6건(Harris 1973, Markowitz 1957, Land & Doig 1960, Knuth 2000, Shaw 1998, Ropke & Pisinger 2006) 및 Gendron & Crainic (1994) Crossref/DOI 대조 완료 |

## 2. 설정 튜닝 과정 (SPP stall 함정 해소)

초기 SPP 워커 배분에서는 `stall >= 1.5s / 3.0s` 조건으로 LNS 워커를 B&B로 넘겼다. 집중 실험 결과 `sp_m200~400` 같은 대형 합성 SPP에서 LNS가 3초간 개선을 못 하면 마지막 LNS 워커까지 B&B로 이탈해 `last_impr_t`가 더 이상 갱신되지 않는 **자기 강화 정체(stall trap)**가 발생했고, 30초 해 품질이 P4 대비 2~6% 악화됐다(`sp_m300_n2000_s1`: 77,147 → 81,801).

이를 순수 **gap 기반 단계적 배분(`5% / 3.5% / 1.5%`)**으로 수정해:
- `sp_m200~400`(gap 5~10%)에서는 3개 LNS 워커가 온전히 유지돼 해 품질을 회복했고(전량 HiGHS 우위),
- `sppaa01/04`(gap < 1%) 및 `sp_m100_n1000/2000`(gap < 4.5%)에서는 3~4스레드 병렬 B&B가 작동해 **6/6 seed 전량 10~16초 내 증명**으로 안정화됐다.

## 4. P0 → P5 전체 진척 요약 및 남은 과제

| 단계 | 핵심 기능 | 30초 최적 증명 (153개) | 주요 성과 |
|---|---|---:|---|
| P0 | 벤치마크 하네스·리더·합성 생성기 | – | 153개 인스턴스 + BKS·지표 체계 확립 |
| P1 | SC Lagrangian(CFT) 휴리스틱·DMS 어댑터 | 49 / 90 (SC) | DMS·SCP 5~30초 해 품질에서 HiGHS 대폭 추월 |
| P2 | 자체 C++17 dual/primal simplex + LU + sifting | – | 전 인스턴스 HiGHS LP와 상대오차 ≤ 1e-6 일치 |
| P3 | LP 기반 B&B, reduced cost fixing, SPP 경로 | 117 / 153 | OR-Library SPP 대부분 증명, SC/SPP 통합 정확해법 |
| P4 | Zero-half·clique 컷, SPP presolve, RINS/LNS | 125 / 153 | 루트 gap 50~75%·노드 70.5% 감소, HiGHS(120) 추월 |
| **P5** | **4스레드 병렬 B&C 트리, SC/SPP 동적 워커 합류** | **132 / 153** | **HiGHS +12개 우위(시간 3.72배)·Gurobi 67/71 동률·SPP vs HiGHS 무패** |

남겨 둔 선택·후속 과제:
1. **`scpnrg`·`scpnrh` 및 대형 `sp` 미세 트레이드오프**: `scpnrg`/`scpnrh`는 즉시 트리 반환으로 5초 해 품질을 보호한 대신 루트 이후 하한 상승(+1~2)이 생략돼 최종 gap %가 P4보다 약 1.2%p 높게 표시된다. `sp_m200~400`은 30초 평균 목적값이 P4 대비 약 +0.2~0.8% 변동(여전히 HiGHS 대비 −1.93% 우위, Gurobi 대비 +0.64%)이 있다.
2. **선택 미구현 항목**: 결정적 병렬 모드(`deterministic=True`), Linux x86-64 Docker/Colima 최종 재확인(P0 이후 미재실행), 미증명 대형 인스턴스(`scpnrg`, `rail507`, `sp_m200~400`) 대상 600초 장기 증명 실행.

## 5. 클린룸·참고문헌

P5에서 추가한 병렬 branch-and-bound 기법(공유 최선 하한 큐·워커별 LP 복제)의 출처(Gendron & Crainic 1994)와 P2~P4 미대조 문헌 6건의 서지·DOI를 모두 `docs/references.md`에 대조·기록했다. 프로젝트 전 과정에서 다른 솔버의 소스는 열람하지 않았으며, HiGHS·Gurobi는 블랙박스 결과 비교에만 사용했다.
