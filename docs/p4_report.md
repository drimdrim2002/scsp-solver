# P4(Branch-and-Cut 강화) 결과 보고

작성일: 2026-11-19 · 대상: `docs/design.md` 6장의 P4 · 결론: **게이트 충족.** 루트 컷이 유지된 90개 인스턴스에서 루트 LP gap을 평균 50~75%(DMS 중앙값 75.0%, 합성 `sp` 중앙값 51.5%, `sppnw` 중앙값 100.0%) 닫았고, 양쪽 모두 증명한 82개 인스턴스의 총 B&B 노드 수를 **62,466 → 18,408 (−70.5%)**로 줄였다. 30초 안 전 seed 최적 증명 수는 **SC 69/90(HiGHS 68 추월), SPP 56/63(HiGHS 52, OR-Library SPP 55/55 전량 증명)**이다.

---

## 1. 구현한 것

설계서의 P4 범위("conflict graph, clique·odd-hole·zero-half cut, 강화 presolve")에 더해, P3에서 미구현·약점으로 남겼던 항목(RINS/이웃 탐색, 트리 속도, 큰 문제 트리 스레드 반환, DMS 시작해 벤치마크)을 함께 마무리했다.

| 구성 | 파일 | 내용 |
|---|---|---|
| LP 행 추가·삭제·상태 저장 | `include/scsp/lp.hpp`, `src/core/lp.cpp` | `LpSolver::add_rows` / `remove_rows` / `row_status` / `row_activity` 구현(P3에서는 선언만). strong branching 뒤 기저와 dual steepest edge 가중치를 함께 복원(`save_state` / `restore_state`) |
| 절단평면 분리 | `include/scsp/cuts.hpp`, `src/core/cuts.cpp` | 덮기/묶기(odd hole) 쪽 **zero-half 컷**(Caprara & Fischetti 1996; Hoffman & Padberg 1993)과 conflict graph **clique 컷**(Hoffman & Padberg 1993) greedy 분리 |
| 루트 컷 라운드 | `src/core/bnb.cpp` (`root_cuts`) | 최대 30라운드, 효율(efficacy) 순 추가, 밀도 한도, 느슨한 컷 삭제. 컷이 루트 gap의 5%도 못 닫으면 전부 제거해 노드 LP가 느려지는 것을 방지. 컷 뒤의 LP 값과 reduced cost로 열 고정을 다시 적용 |
| 트리 탐색 강화 | `include/scsp/bnb.cpp`, `include/scsp/bnb.hpp` | 큐 노드의 부모 기저 재사용(`node_basis`), 노드별 reduced cost fixing(`local_fix`), strong branching 조기 중단(`strong_lookahead = 4`), 트리 내부 RINS(`Search::rins`), 제한 트리에서 첫 해를 찾으면 바로 정확한 트리로 전환(`SWITCH`) |
| 일반 0-1 경로 강화 | `src/core/bin_solver.cpp` | 분할 문제 presolve(`presolve_bin`: 중복 열, 분할 행 포함 관계, 단일 열 행 고정 — Borndörfer 1998). 남는 스레드(`threads - 1`)가 최고해 주변 RINS + 고정 이웃 탐색(LNS)을 병렬 실행 |
| 큰 SC 트리 스레드 반환 | `src/core/sc_solver.cpp` (`run_hybrid`) | 소수 비용이면서 예상 루트 LP 시간이 제한의 2%를 넘으면 LP를 시작하지 않음(`no_lp`). 루트 LP 시간 한도(4%), 남은 시간 내 예상 노드 수 하한, 최근 하한 상승 속도 기준(`tree_giveup = 3.0`)으로 가망이 없으면 트리 스레드를 예비 휴리스틱 worker로 전환 |
| DMS 시작해(warm start) 도구 | `python/scsp/bench/warm.py`, `worker.py`, `run.py` | BKS 기준 약 +2%의 시작해 2종(`near`: 최선해 destroy/repair, `indep`: 빈 해에서 greedy+하강) 생성·저장(`benchmarks/warm_starts*.json`) |
| Python·테스트 | `src/bindings/module.cpp`, `python/scsp/solve.py`, `tests/test_p4.py`, `tests/test_lp_rows.py`, `tests/test_warm.py` | `cuts`, `tree_giveup` 인자 및 `LpSolver.add_rows`/`remove_rows`/`row_status`/`row_activity` 노출. 단위 테스트 총 **162개 통과**(OR-Tools 테스트 별도), `-Wall -Wextra -Wpedantic -Werror` 빌드 통과 |

## 2. 설정 확정 실험 (분기 방식 · Strong Branching · LP 연결)

게이트 측정 전 세 가지 설정을 순차 실험(30초, 4스레드, `python -I`)으로 비교해 확정했다.

### 2.1 분할 문제 분기 방식: Ryan–Foster vs 변수 reliability branching

기존 `branch_pair`(Ryan–Foster)는 strong branching·의사비용 없이 분수도가 0.5에 가장 가까운 행 쌍만 고르는 반면, `branch_var`는 reliability branching + strong branching + 한쪽 불가능 시 즉시 고정이 작동한다.

| 인스턴스 (seed 1, 30초) | `ryan_foster = true` | `ryan_foster = false` (기본 `look=8`) | `ryan_foster = false`, `look=4` |
|---|---|---|---|
| `sppaa01` | 미증명 (1428노드, 하한 55999) | **13.04초 증명** (162노드) | **11.19초 증명** (158노드) |
| `sppaa04` | 미증명 (2801노드, 하한 26251) | **13.67초 증명** (251노드) | **13.10초 증명** (254노드) |
| `sppkl02` | 1.24초 (151노드) | **0.57초** (37노드) | **0.56초** (37노드) |
| `sp_m100_n1000_s1` | 미증명 (하한 24346) | 미증명 (하한 24666) | **28.08초 증명** (9126노드) |
| `sp_m100_n2000_s1` | 미증명 (하한 22346) | 미증명 (하한 22318) | 미증명 (하한 **22488**) |

→ **`ryan_foster = false`를 기본값으로 확정**(옵션으로 코드는 유지).

### 2.2 Strong branching 파라미터

기존 기본값(`strong_cands = 8, strong_lookahead = 8, strong_iters = 100, reliability = 2`)에서는 후보 상한과 조기 중단 횟수가 같아 lookahead가 실제로 발동하지 않았다.

- `cands=16, look=4, rel=4` 및 `cands=12, look=4, rel=8`: strong branching 비중이 커져 9개 주요 SC 증명 문제 합계가 115.5초 → 129.5초·124초+로 느려졌다.
- `iters=50`: DMS에서는 소폭 빨랐으나 `scpnrf1`(26.8→28.7초), `scpnre3`(18.4→19.3초), `sp_m100_n1000_s1`(미증명)에서 분기 품질이 떨어져 노드가 늘었다.
- **`strong_lookahead = 4`만 적용(`cands=8, iters=100, rel=2`)**: `sppaa01`(13.0→11.2초), `sppaa04`(13.7→13.1초), `sp_m100_n1000_s1`(미증명→28.1초), `scpnrf1`(26.8→24.6초), `scpnre3`(18.4→16.4초), `dms_K200/K500` 모두 개선됐다.

→ **`strong_lookahead = 4`로 확정.**

### 2.3 루트 LP → SC 휴리스틱 연결(`lp_adopted`)

큰 SC 문제에서 루트 LP의 reduced cost를 휴리스틱 worker의 열 제거에 쓰는 연결을 껐을 때(`SCSP_NO_LP_ADOPT`)와 켰을 때를 3 seed로 비교했다.

- `scpnrh1~3` (9회): 켠 쪽 **9/9 BKS 달성**, 끈 쪽 7/9.
- `dms_K500_n30000_tight_s1`: 켠 쪽 30초 평균 3235.97 (끈 쪽 3236.80).
- `dms_K300_n20000_s1`: 켠 쪽 30초 평균 3194.45 (끈 쪽 3196.40).
- `dms_K1000_n60000_s1`, `dms_K2000_n60000_s1`: `no_lp` 규칙이 루트 LP 자체를 건너뛰고 즉시 4스레드 휴리스틱으로 돌므로 P1 대비 회귀가 이미 해소됐다(30초에서 기존 BKS 경신).
- `dms_K200/K300_n2000_s1` 증명 시간도 켠 쪽이 약 0.8~1.0초 빨랐다.

→ **`lp_adopted` 기본 켜짐 유지.** 아울러 `no_lp`로 LP를 건너뛴 경우에도 `stats["tree_gave_up"]`이 기록되도록 수정했다.

읽을 점:
- **DMS와 `sp`에서 효과가 가장 크다.** DMS 2000열은 zero-half 컷이 루트 gap의 약 75%를 닫으면서 노드 수가 **50~100분의 1**로 줄었고, `dms_K500_n2000_s1`과 `sp_m100_n1000_s1`은 컷이 있어야 30초 안에 증명된다. `sppnw`에서는 26개 중 16개가 루트에서 gap이 100% 닫혔다.

## 5. 한계와 P5로 넘길 과제

1. **합성 `sp` 100행 증명 안정화**: `sp_m100_n1000_s1`(2/3 seed 증명)과 `sp_m100_n2000_s1`(1/3 seed 증명)은 30초 경계에 걸쳐 있다. 현재 일반 0-1 경로(`bin_solver`)의 B&B 트리는 여전히 1스레드이고, 컷은 루트에서만 생성된다.
2. **조밀 SC에서의 컷 선별**: `scpb`·`scpd`·`scpnre5`처럼 gap 감소가 5~15%인 조밀 덮기 문제에서는 컷을 남겨 두면 노드 LP가 느려져 시간상 소폭 손해가 난다. 컷 밀도·유지 임계값(현재 5%)이나 비활성 컷 정리(cut aging)를 다듬을 여지가 있다.
3. **`scpnrh` 트리 반환 지연**: `scpnrh1`은 23~26초, `scpnrh2·3`은 약 6초에 트리 스레드가 반환돼 5초 시점에서 P1보다 약간 밀리는 경우가 남는다.
4. **병렬 트리 탐색 (P5)**: SC·SPP 모두 B&B 트리는 1스레드다. P5에서 병렬 B&B(또는 concurrent 전략)를 붙이면 `dms_K200_n10000`, `sp_m100`, `scpnre/f`의 증명 시간을 더 줄일 수 있다.
5. **미완료 보조 항목**: `docs/references.md` 미대조 서지 6건(Harris 1973, Markowitz 1957, Land & Doig 1960, Knuth 2000, Shaw 1998, Ropke & Pisinger 2006)의 Crossref 확인, Linux x86-64 빌드 확인, 600초 장기 증명 실행.
