## 2. 기준 실행 요약

조건: Apple M4(성능 코어 4개), 4스레드, seed 1·2·3, 실행마다 별도 프로세스로 한 번에 하나씩, 시간 제한 60초.
Gurobi 13.0.2는 크기 제한(변수 ≤ 2000, 제약 ≤ 2000) 안의 71개 인스턴스만, HiGHS 1.16.0은 156개 전부.
전체 표는 `benchmarks/results/baseline_report.md`, 원자료는 `benchmarks/results/runs/*.jsonl`.

- 실행 수: Gurobi 213개(최적 증명 201, 시간 초과 12), HiGHS 468개(최적 증명 386, 시간 초과 79, 강제 종료 3).
- Gurobi와 HiGHS가 둘 다 푼 71개에서 Gurobi가 더 좋은 인스턴스는 5초 11개, 30초 5개이고 나머지는 동률이다. HiGHS가 더 좋은 경우는 없다.
- P1의 비교 대상인 SC 세트에서 HiGHS의 BKS 대비 평균 격차:

| 세트 | 개수 | 5초 % | 10초 % | 30초 % | 60초 % | 60초 안에 증명한 실행 |
|---|---|---|---|---|---|---|
| scp4·5·6·a·b·c·d·e | 50 | 0.00 | 0.00 | 0.00 | 0.00 | 150 / 150 |
| scpnre / scpnrf | 5 / 5 | 0.00 / 1.03 | 0.00 / 1.03 | 0.00 / 0.51 | 0.00 / 0.51 | 13 / 14 (각 15) |
| scpnrg / scpnrh | 5 / 5 | 0.29 / 0.64 | 0.29 / 0.53 | 0.13 / 0.21 | 0.08 / 0.11 | 0 / 0 |
| rail | 3 | 58.4 | 44.7 | 0.13 | 0.00 | 6 / 9 |
| 합성 DMS | 17 | 1.49 | 0.87 | 0.42 | 0.13 | 34 / 51 |

(P1 뒤 덧붙임: 큰 합성 DMS 5개의 BKS가 scsp 값으로 갱신돼서, 다시 만든 `baseline_report.md`의 HiGHS DMS 격차는
위 표보다 크다 — 2.61 / 1.99 / 1.53 / 1.23. `docs/p1_report.md` 3장.)

**P1에 중요한 관찰**: HiGHS는 scp4~scpe 50개 전부에서 5초 안에 최적값에 도달한다. 따라서 이 50개에서는
어떤 솔버도 HiGHS보다 "더 좋은" 값을 낼 수 없고 동률이 최선이다(P1 통과 기준 해석에 영향 — 5장).

기준 솔버가 해를 못 낸 경우:

- `sppnw05`(288,507열): HiGHS가 60초 안에 해를 못 냈고 제한을 넘겨 약 94초 뒤에 끝났다(3회 모두).
- `sppnw16`(148,633열), `sppus03`(85,552열): HiGHS가 60초 안에 해를 못 냈다.
- `sppus01`(1,053,137열): HiGHS 실행이 240초(2×제한 + 120초)를 넘겨 강제 종료됐다(3회 모두).

## 3. 5/10/30초 값을 trace에서 읽는 방식의 검증

설계서는 시간 제한 5/10/30/60초를 각각 실행하는 것으로 적었지만, 실제로는 60초 실행 한 번의 trace에서 5/10/30초 값을
읽었다(따로 돌리면 기준 실행만 약 5시간). 7개 (솔버, 인스턴스) 조합에서 시간 제한을 따로 준 실행(seed 1)과 비교했다
(`benchmarks/results/validation/`).

| 솔버 | 인스턴스 | 5초: 따로 실행 / trace | 10초 | 30초 |
|---|---|---|---|---|
| HiGHS | dms_K200_n2000_s1 | 3862.08 / 3862.08 | 3830.12 / 3830.12 | 3830.12 / 3830.12 |
| HiGHS | dms_K500_n30000_s1 | 3510.44 / 3510.44 | 3469.60 / 3469.60 | 3373.91 / 3373.91 |
| HiGHS | rail507 | **176 / 188** | 176 / 176 | 175 / 175 |
| HiGHS | scpnrg1 | 176 / 176 | 176 / 176 | 176 / 176 |
| HiGHS | scpnrh1 | 64 / 64 | 64 / 64 | 64 / 64 |
| Gurobi | dms_K500_n2000_s1 | 4112.56 / 4112.56 | 같음 | 같음 |
| Gurobi | sp_m200_n2000_s1 | 50636 / 50636 | 49035 / 49035 | 49035 / 49035 |

21건 중 20건이 일치한다. rail507의 5초 값만 다르다(따로 실행 176, trace 188). 같은 seed라도 해를 찾는 시각이 실행마다
조금 달라지기 때문으로 보이며, 5초 근처에서 해가 바뀌는 인스턴스는 trace 값이 ±한 단계 흔들릴 수 있다.

## 4. 설계서와 달라진 점, 알려 둘 점

- **시간 제한 격자**: 위 3장대로 60초 실행 + trace 읽기로 바꿨다. `docs/design.md` 5.3절에 반영했다. 최적 증명용 600초 실행은 하지 않았다(P3에서).
- **BKS 문헌값 정정**: scpnre5의 최적값은 28이다(초안의 27은 틀림, HiGHS가 28을 증명).
  sppaa01 = 56137, sppaa04 = 26374, sppnw02 = 105444는 문헌끼리 값이 달랐고 HiGHS가 증명한 값으로 확정했다.
  sppus01 = 10036은 HiGHS가 풀지 못해 문헌값(Borndörfer 1998)만으로 적었다.
- **최적이 증명되지 않은 15개**: scpnrh1–5(문헌 최고값), 큰 합성 DMS 5개와 합성 SP 5개(기준 실행 최고값). P1 이후 더 좋은 값이 나오면 `python -m scsp.bench.bks`로 갱신된다.
- **MIPLIB 3개는 OR-Library와 같은 문제**라 집계에서 `miplib` 세트를 따로 두었다.
- **합성 DMS의 라이더 값**(속도·용량·비용)은 OGC 2024 예시 수준으로 정한 것이고 대회 파일을 복사한 것이 아니다. 작은 DMS(번들 ≤ 2000) 10개는 Gurobi가 0.5~2초에 최적을 증명할 만큼 쉽다.
- **합성 SP는 생각보다 어렵다**: 200행×2000열인데 Gurobi도 60초에 증명하지 못한 인스턴스가 있다.
- **승인 없이 한 일**: 빌드에 필요해 `ninja`를 pip로 추가 설치했다(승인받은 것은 pybind11·cmake·scikit-build-core). 참고문헌 대조 중 하위 에이전트가 논문 PDF 등 약 49 MB를 임시 폴더에 내려받았고, 대조 뒤 모두 지웠다(저장소에는 없음).
- **기준 실행 중 간섭**: SPP 세트 기준 실행이 도는 동안 P1 컴파일과 기능 시험을 효율 코어에서 돌렸다. SC 세트와 Gurobi 실행은 그 전에 끝났으므로 영향이 없고, SPP 세트의 HiGHS 시간에는 약간의 영향이 있을 수 있다.
- **커밋은 하지 않았다**(요청 시에만).

## 5. P1 진입 전(또는 진행 중) 결정할 점

1. **P1 통과 기준의 동률 처리**: "5/10/30초 목적값이 highspy보다 좋은 인스턴스 ≥ 80%"를 엄격한 우위로 읽으면, HiGHS가 5초 안에 최적에 도달하는 scp4~scpe 50개(전체 90개의 56%) 때문에 달성할 수 없다. "나쁘지 않은 인스턴스 ≥ 80%" 또는 "HiGHS가 5초에 최적이 아닌 인스턴스 중 ≥ 80%" 같은 해석이 필요하다. P1 보고서에는 승/무/패를 모두 적는다.
2. **warm start 조건**: DMS 실사용은 ALNS 해를 warm start로 준다. 기준 실행은 warm start 없이 했다. warm start를 준 비교(`--warm-start`, `highs-dms` 설정)를 추가할지.
3. **시간 제한별 전체 격자 실행**(약 5시간)을 한 번은 해 둘지, trace 읽기로 계속 갈지.
4. **추가 비교 대상**: 크기 제한이 없는 OR-Tools CP-SAT를 넣을지.
5. **더 어려운 DMS 인스턴스**: 실제 대회 데이터로 만든 번들 풀을 벤치마크에 넣을지(DMS 폴더는 읽기만 가능하므로 사용자 결정 필요).
6. **Linux 확인 주기**: P1 코드의 Linux 빌드 확인은 colima를 다시 켜야 한다(사용자 승인 필요).
